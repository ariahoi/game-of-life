# Игра «Жизнь» Конвея — дизайн

Дата: 2026-11-07
Статус: на ревью

## 1. Цель

**Сказано пользователем:** игра нужна, чтобы «поиграть и посмотреть». Нужны, помимо базы: большое поле с зумом, другие правила, красивая визуализация.

**Допущения:** одна интерактивная веб-страница без установки, работает на компьютере и телефоне. Правило по умолчанию — классическое B3/S23.

**Критерий успеха:** можно нарисовать клетки, запустить симуляцию, менять скорость/правило/масштаб и смотреть на плавную красивую анимацию на поле до 1000×1000.

**Вне рамок (YAGNI):** библиотека готовых фигур, импорт/экспорт RLE, бесконечное поле, WebGL, история/отмена, сохранение между сессиями.

## 2. Выбранный подход

Canvas 2D + типизированные массивы, ограниченное поле, замкнутое в тор. Один файл `index.html` без внешних зависимостей.

Отклонено: WebGL (сложнее в 2–3 раза, не нужно для целевых размеров), бесконечное поле/HashLife (плохо сочетается с возрастом/следами, избыточно).

## 3. Архитектура

Все блоки — внутри `index.html`. Поток данных однонаправленный: `Input`/`UI` → меняют `Life` и камеру → `Renderer` читает.

### 3.1 `Life` — движок (в `<script id="life-engine">`, без обращений к DOM)

- Поле `W×H`, тор. Буферы: `cells: Uint8Array` (0/1), `next: Uint8Array`, `age: Uint8Array` (0–255, с насыщением), `trail: Uint8Array` (0–255).
- Правило: `{ birth: number, survive: number }` — 9-битные маски (бит *n* = «n соседей»).
- `parseRule(str)` — принимает `B<цифры 0–8>/S<цифры 0–8>` без учёта регистра, пробелов по краям; любая часть может быть пустой (`B2/S`). Цифры вне 0–8, лишние символы, отсутствие `/` → выбрасывает `Error`.
- `step()`:
  - новая клетка жива, если (мертва и `birth` содержит n) или (жива и `survive` содержит n);
  - `age`: у живой после шага — `min(age+1, 255)` если выжила, `1` если родилась; у мёртвой — `0`;
  - `trail`: у клетки, умершей на этом шаге, — `255`; у остальных мёртвых — `max(trail − TRAIL_DECAY, 0)`, где `TRAIL_DECAY = 16` (≈16 поколений до затухания); у живых — `0`;
  - `generation += 1`, пересчёт `population`.
- `get(x,y)`, `set(x,y,alive)` — координаты оборачиваются по тору; `set(…, true)` ставит `age = 1`, `trail = 0`; `set(…, false)` обнуляет `age` и `trail`.
- `clear()`, `randomize(density, rng = Math.random)`, `resize(newW, newH)` — переносит содержимое в центр нового поля, не влезшее обрезается.
- Свойства: `width`, `height`, `generation`, `population`, `rule`.
- Экспорт: `globalThis.LifeEngine = { Life, parseRule }`.

### 3.2 `Renderer`

- Внеэкранный canvas `W×H`, `ImageData`, 1 пиксель = 1 клетка.
- Цвета: заранее посчитанная LUT на 256 значений возраста: почти-белый/голубой (age 1) → бирюзовый → глубокий фиолетовый (age ≥ ~100). След — тусклый фиолетовый с яркостью ∝ `trail`. Фон — почти чёрный с синевой (`#0a0c14`).
- Переключатель «следы» выключает отрисовку `trail`.
- Вывод на экранный canvas через `drawImage` с `imageSmoothingEnabled = false` и трансформацией камеры `{ x, y, zoom }` (x, y — координаты клетки в центре экрана; zoom — пикселей экрана на клетку). Учитывается `devicePixelRatio`.
- Сетка рисуется поверх, если `zoom ≥ 8` экранных пикселей.
- Отрисовка тора не повторяется: показывается одна копия поля, вокруг — фон.

### 3.3 `Input`

- ЛКМ / один палец: рисование. Режим мазка определяется первой клеткой: пустая → мазок оживляет, живая → стирает. Между событиями указателя клетки интерполируются линией (Брезенхем), чтобы при быстром движении не было пропусков.
- ПКМ-перетаскивание или пробел+ЛКМ: панорама. Контекстное меню на canvas отключено.
- Колесо: зум к точке под курсором, множитель 1.15 за щелчок, пределы zoom 0.5…64.
- Два пальца: пинч-зум + панорама одновременно.
- Используются Pointer Events; `touch-action: none` на canvas.

### 3.4 `UI` и игровой цикл

- Панель (полупрозрачная, левый верхний угол, сворачивается в одну кнопку):
  - Старт/Пауза, Шаг, Очистить, Случайно + ползунок плотности (5–60 %, по умолчанию 25 %);
  - Скорость: 1–60 поколений/с (по умолчанию 15);
  - Правило: выпадающий список — Conway `B3/S23`, HighLife `B36/S23`, Seeds `B2/S`, Day & Night `B3678/S34678`, Своё; текстовое поле для правила;
  - Размер поля: 200×150, 400×300, 600×400, 1000×1000;
  - Переключатель «Следы»; кнопка «Вписать в экран».
- Статус (мелко, нижний левый угол): поколение, популяция, текущее правило.
- Горячие клавиши: Пробел — старт/пауза срабатывает при отпускании, если пока он был зажат, не было перетаскивания ЛКМ (иначе это была панорама), N — шаг, C — очистить, R — случайно, F — вписать в экран.
- Цикл: `requestAnimationFrame`; аккумулятор времени, шагов за кадр = накопленное / (1/скорость); накопление ограничено 0.25 с, шагов за кадр не более 8.
- Отрисовка каждый кадр (дешёвая), шаги — по аккумулятору.

## 4. Пограничные случаи

| Ситуация | Поведение |
|---|---|
| Некорректное правило в поле ввода | Поле подсвечивается красным, действует прежнее правило; при исправлении — применяется |
| Смена размера поля | Рисунок переносится в центр, лишнее обрезается; камера вписывает поле |
| Первый запуск | Поле 400×300, случайное заполнение 25 %, камера вписывает поле, пауза |
| Вкладка была в фоне | Аккумулятор ≤ 0.25 с — нет рывка «догонки» |
| Изменение размера окна | Canvas подстраивается, камера сохраняет центр |
| Рисование за пределами поля | Игнорируется (тор применяется только к соседям в `step`, не к вводу) |

## 5. Тестирование

### 5.1 Автотесты движка

`tests/life.test.mjs`, запуск `node --test tests/`. Тест читает `index.html`, вырезает содержимое `<script id="life-engine">`, исполняет в `node:vm` и берёт `LifeEngine`.

Проверки:
1. `parseRule`: `B3/S23`, `b36/s23`, `B2/S`, `B3678/S34678` разбираются в правильные маски; `B9/S2`, `xyz`, `` (пусто), `B3S23` → ошибка.
2. Блок 2×2 неизменен после 5 шагов.
3. Мигалка: период 2, после 1 шага — повернута.
4. Глайдер: через 4 поколения сдвинут на (+1, +1).
5. Тор: на поле 20×20 глайдер через 80 поколений совпадает с исходным состоянием.
6. HighLife vs Conway: конфигурация, где у мёртвой клетки ровно 6 соседей — рождается при B36, не рождается при B3.
7. `age`: растёт у выживших, = 1 у новорождённых, = 0 у мёртвых; насыщение на 255.
8. `trail`: = 255 у только что умершей, убывает на 16 за поколение до 0, = 0 у живых.
9. `resize`: фигура переносится в центр нового поля; `population` сохраняется, если влезает.
10. `generation` и `population` корректны после шагов, `clear`, `randomize` (детерминированный rng).

### 5.2 Ручная проверка в браузере

Скриншоты: стартовый экран; идущая симуляция с цветами возраста и следами; крупный зум с сеткой; неверное правило (красное поле). Проверка консоли на ошибки. Поле 1000×1000 при 30 пок./с — визуально плавно.
